2. Bot WhatsApp — state machine

Cada chat tiene un flow_state.step en la BD. El handler dispatcha según el step actual.

Nota: Si el cliente escribe algo fuera del flujo (ej. "¿hasta qué hora abren?"), el bot reenvía el último prompt. Si pide hablar con humano o el flujo no puede continuar, escala a chat.status='human' y el bot se calla.

4. Pasarela Wompi — checkout y webhook

Cómo se cierra el pago (mock por ahora, listo para reemplazar por Wompi real).

flowchart LR
    BotSend[Bot manda link
Wompi al cliente] --> Cliente1([📱 Cliente abre
el link])
    Cliente1 --> Checkout[/wompi/checkout/:orderId
página HTML/]
    Checkout --> Botones{Cliente decide}
    Botones -->|✅ Aprobar pago| Webhook[/POST /api/wompi/webhook
status=APPROVED/]
    Botones -->|❌ Rechazar| Noop[Solo log
no cambia estado]

    Webhook --> CheckNuevo{order.status = 'nuevo'?}
    CheckNuevo -->|No| Idempotent[Ignora
idempotente]
    CheckNuevo -->|Sí| UpdatePagado["update orders
SET status='pagado'"]

    UpdatePagado --> Notif["Manda WhatsApp:
'¡Edison, pago recibido!
Tu pedido pasa a cocina 🥪'"]
    Notif --> FinalState["chat.flow_state.step
= 'finalizado'"]
    FinalState --> KanbanAuto["Frontend ve el cambio
(polling 4s) → tarjeta
aparece en columna 'pagado'"]
